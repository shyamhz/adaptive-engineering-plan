## What this is

This is not a tutorial list. It is an **adaptive execution system** with a stable strategic spine and an adaptive execution layer:

- **Stable core:** 7 pillars (web, systems, graphics, AI leverage, real construction, public proof, career distribution). Does not change mid-cycle.
- **Adaptive layer:** versions, hosts, agent choice, project slice, posting cadence. Reviewed every 4th week.
- **Tactical experiments:** 1-week time-boxed bets with kill criteria. No shiny-object drift.

Standard at the end: *“I can build it manually. I understand how it works. I can make an agent build it faster. I can tell when the agent is wrong. I can measure the result. I can explain the architecture. And I have public evidence that I actually did it.”*

## Project ladder

- **L1:** static portfolio + JS primitives (todo, fetch-list, emitter) — manual, deployed
- **L2:** `fullstack-notes` (React+TS+Node+Postgres+auth+tests+Docker) — live
- **L3:** prod-hardened (Redis, rate-limit, Pino, /metrics, k6 + fix) + `c-labs` + `three-playground`
- **L4 (one):** realtime presence / 100k-particle WebGPU / C++ file-server vs Node — benchmarked
- **L5 (one):** flagship — live URL, arch diagram, tests+CI, observability, docs, 2 writeups, postmortem, demo

Flagship candidates (locked C5): **A.** WebGPU playground+backend · **B.** realtime viz+ingest · **C.** agent-eval harness.

## AI usage (A→D)

- **C1 Stage A:** no agent for core code — tutor/quiz/review only
- **C2–C5 Stage B:** you write critical paths, agent scaffolds; every diff read; `agent-review.md` with ≥1 rejection/week
- **C6+ Stage C→D:** SPEC.md + AGENTS.md + eval checklist (builds? tests? perf? auth? demo?) + `agent-failures.md`
- **Bans:** no secrets in prompts, no `.env` committed, no agent→main without green CI

## Public proof (evidence > frequency)

- **Peerlist:** per release only — top 3 + live links + outcome metric
- **GitHub:** chunked commits, PR+Actions from C2, demo-top READMEs, audit W32/W40
