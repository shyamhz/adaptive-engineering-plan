## What This Is

This is not a tutorial list.

It is an **adaptive execution system** with a stable strategic spine
and an adaptive execution layer:

- **Stable core**

  7 pillars — web, systems, graphics, AI leverage, real construction,
  public proof, career distribution. Does not change mid-cycle.

- **Adaptive layer**

  Versions, hosts, agent choice, project slice, posting cadence.
  Reviewed every 4th week.

- **Tactical experiments**

  1-week time-boxed bets with kill criteria. No shiny-object drift.

The standard at the end:

> *“I can build it manually. I understand how it works.*
> *I can make an agent build it faster. I can tell when the agent is wrong.*
> *I can measure the result. I can explain the architecture.*
> *And I have public evidence that I actually did it.”*

## Project Ladder

- **L1 — Manual primitives**

  Static portfolio + JS primitives (todo, fetch-list, emitter).
  Manual, deployed.

- **L2 — Integrated app**

  `fullstack-notes` — React + TS + Node + Postgres + auth + tests + Docker.
  Live.

- **L3 — Production-hardened**

  Redis, rate-limit, Pino, `/metrics`, k6 + fix.
  Plus `c-labs` + `three-playground`.

- **L4 — One difficulty spike (pick one)**

  Realtime presence, or 100k-particle WebGPU, or C++ file-server vs Node.
  Benchmarked.

- **L5 — One flagship**

  Live URL, arch diagram, tests + CI, observability,
  docs, 2 writeups, postmortem, demo.

Flagship candidates (locked at C5):

- **A.** WebGPU playground + backend
- **B.** Realtime viz + ingest
- **C.** Agent-eval harness

## AI Usage (A → D)

- **C1 — Stage A**

  No agent for core code. Tutor / quiz / review only.

- **C2–C5 — Stage B**

  You write critical paths, agent scaffolds.
  Every diff read. Keep `agent-review.md` with ≥1 rejection per week.

- **C6+ — Stage C → D**

  SPEC.md + AGENTS.md + eval checklist
  (builds? tests? perf? auth? demo?) + `agent-failures.md`.

- **Bans**

  No secrets in prompts. No `.env` committed.
  No agent → main without green CI.
